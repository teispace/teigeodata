# teigeodata in WebAssembly

The `Engine` and the functions of `teigeodata-api` for browsers, Deno, Bun, Node.js and
Workers, built with wasm-bindgen ([research](../../docs/02-research/notes/node-wasm-packaging.md),
D-291 to D-293). `src/lib.rs`, `js/index.js` and `js/index.d.ts` are generated by
`cargo xtask bindings`; `js/node.js` and `js/workerd.js` are the hand-written entries.

Two npm packages, each a set of pack components with the same API, and the browser store as
a subpath of the first, its own module (D-375):

| Import | Components | Budget (module, gzip -9) |
|---|---|---|
| `teigeodata-wasm` | every one | 262,144 B |
| `teigeodata-wasm-lookup` | every one but `search` and `substring` (no `fold`) | 153,600 B |
| `teigeodata-wasm/store` | every one, and `Store` | 450,560 B |

`Store` (`src/store.rs`, the `store` feature) is the native store's client core
(`teigeodata_sync::session`) over a `StoreHost`: files shaped as OPFS sync access handles, and
`fetch`. Every package has the reader, `installedSections` and `Engine.openInstalled`
(`src/sections.rs`, D-373); a page reads the store's `journal` file with `JSON.parse` (its
`packs` are `JournalRecord`s), and the store module checks it with `parseJournal`.

## Build and test

Tools: the `wasm32-unknown-unknown` target, `wasm-bindgen-cli` at the exact version the crate
pins (`cargo install wasm-bindgen-cli --version 0.2.130 --locked`) and binaryen's `wasm-opt`
(version 133).

```sh
cargo xtask package-wasm --test        # every variant under target/wasm/ (the store in
                                       # full/store/), parity on Node.js, Bun and Deno where
                                       # installed, the store's checks on Node.js and Bun
cd bindings/wasm/test && npm ci        # Playwright and Miniflare, pinned by the lock file
node browser.mjs ../../../target/wasm/full ../../parity.json   # Chromium, Firefox, WebKit
node workerd.mjs ../../../target/wasm/full ../../parity.json   # workerd
```

`test/checks.mjs` holds the checks and uses no host API; the runners load the package and
the fixtures. `test/store.mjs` runs the store over an in-memory host against
`fixtures/store-repo/`, a signed repository under the keys of `fixtures/store-root.json`
(`teigeodata-api`'s `the_bindings_store_repo_is_current` keeps both current). CI runs all of them (`wasm.yml`).
