What it answers

Everything an app needs to know about a place

Nine kinds of question, each answered on the device from a memory-mapped file, with the source of every value named.

Reverse geocoding

The whole hierarchy

Country, province, district, local level and ward: every unit with its ISO 3166 code, parents and children, and an ID that survives data updates.

The guide

Boundaries

Any unit’s outline as a GeoJSON Feature at the detail you ask for, ready for MapLibre, Leaflet, OpenLayers, Shapely or Turf.

The guide

Exact timezones

The IANA zone at any point as its boundaries draw it; offsets, transitions and skipped or repeated local times from the tzdb rules in the pack.

The guide

Elevation

A height for every place and at any point: metres above EGM2008, interpolated between samples, with its source named.

The guide

Postal codes

Look a code up, complete one as it is typed, list a unit’s codes, or find the code at a point, with each code’s scheme and validity.

The guide

Nearby and distance

The places within a radius of a point or nearest a place, nearest first; great-circle distance and bearing between any two.

The guide

Local names and population

Names in each language and script, written ones kept apart from transliterations, corrections reviewed against cited sources; population with where it came from.

How it works

From open sources to a file you can trust

The work happens once, in the forge. Your app gets the result: one verified file, no service to call.

  1. 1

    Open sources

    OpenStreetMap, GeoNames, Wikidata, official boundaries, terrain models and tzdb, each pinned by hash.

  2. 2

    The forge

    Cleans, deduplicates and links them; checks spellings, heights and outlines against gates that fail the build.

  3. 3

    A verified pack

    One compact file per country or region: every section hashed and checked as it is read, its sources credited inside.

  4. 4

    Your app

    Memory-mapped by the engine in any language, bundled or downloaded on demand. Queries never touch the network.

In your app, offline

Bundle a pack and every query runs on the device. The store downloads, verifies and keeps the countries your users pick.

Questions

Frequently asked

What is teigeodata?+

An open-source geodata SDK. It answers where places are and what is at a point (search, reverse geocoding, the admin hierarchy, boundaries, timezones, elevation and postal codes) from compact verified packs that work offline, with the same API in twelve languages.

Does it need a network connection or an API key?+

No. Every query runs on a pack on the device or server, and every section of a pack is hashed and checked as it is read. A network is only used to download a pack; the store, which fetches countries on demand from a signed catalog, goes live with the first catalog release.

Which countries are covered?+

Nepal in full, down to wards, plus the world's countries, first-level units and cities of 5,000 or more, and India's districts and towns. Coverage grows by data releases: India, South Asia, Asia, the USA, then the rest of the world.

Can I store and redistribute the results?+

Yes. The code is Apache-2.0. The main data build is under ODbL and the lite build under CC BY 4.0, both of which allow keeping, shipping and redistributing the data with the credits each pack carries.

How accurate is it?+

Coordinates and elevation come first: the target is a vertical error of at most 50 m at the 90th percentile, and each target is a gate a build must pass. Names follow official sources and each country’s lexicon. The figures ship in every pack’s summary.

How does it handle disputed borders?+

From one stated perspective, recorded in each country's profile with its sources: Nepal's official map of 2020, including Kalapani, Lipulekh and Limpiyadhura.

Can it replace a Nominatim server?+

For lookups by name and point, yes: tgd serve answers Nominatim-compatible search and reverse routes from a pack, with a few megabytes of memory.
