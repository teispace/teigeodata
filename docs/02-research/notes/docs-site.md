# The docs site

## 1. Question

Phase 7 (milestone M7, ADR-0024): a public site with guides per language, a reference
generated from the API, per-country pages from the data, measured pages from the gates, and an
in-browser playground on the WebAssembly build. Which stack and versions, how the site is
built and deployed with no server, how examples are kept true (executed, their output checked),
how the reference is generated without a second copy of the API, and what the playground runs
on.

## 2. Summary and recommendation

- **Stack:** Fumadocs 16.19.3 (`fumadocs-core`, `fumadocs-ui`) with `fumadocs-mdx` 15.6.2 on
  Next.js 16.4.6, React 19.3.1, Tailwind CSS 4.3.5 and TypeScript 7.0.2, in `site/`, with npm
  and a lock file (as `bindings/wasm/test`). The layout follows the official static-export
  template (`create-fumadocs-app` 16.3.5, `+next+fuma-docs-mdx+static`): `output: 'export'`,
  the Macro API (`defineDocs` from `fumadocs-mdx/macro` in `lib/source.ts`), search as a
  prebuilt Orama index (`staticGET` and `useStaticSearch`), and `llms.txt`,
  `llms-full.txt` and a Markdown copy of every page for agents.
- **No network at build time beyond npm:** system font stack instead of `next/font/google`;
  no analytics, no third-party scripts. The playground's map draws only our own data.
- **Deploy (D-353, 2026-11-16):** Vercel, project `teigeodata-docs` in the `teispace` team, at
  `https://teigeodata.teispace.com`: the landing page at `/`, the docs at `/docs`, the
  playground at `/playground` (no base path). CI builds and checks the static export, then
  force-pushes it as one commit to the branch `docs-site`; Vercel, connected to the repository
  with `docs-site` as its production branch, no build step and every other branch ignored,
  serves it. No token or secret. GitHub Pages is left to the signed catalog (ADR-0037). The
  first plan was GitHub Pages under `/teigeodata/`; one repository has one Pages site.
- **Examples are programs, not snippets.** Every example on the site is a file under
  `site/examples/<language>/` that is built and run against a real released pack
  (`world-np-lite.tgd` of `data-2026.11.14.3`, CC BY 4.0, 15.6 MB, pinned by SHA-256); its
  output is checked in next to it, and `cargo xtask docs-examples --check` reruns each one and
  fails on any difference. Pages include the code and its output from those files (Fumadocs'
  `<include>`), so what a reader sees is what ran.
- **The reference is generated by the bindings generator** (`cargo xtask bindings`) from the
  IDL, with the same naming filters the bindings use, as checked-in MDX; `--check` already
  fails on drift, so the reference cannot fall behind the API.
- **Per-country and measured pages** are generated from `data/countries/` and the gates'
  checked-in reports by an xtask, checked in, drift-checked.
- **Playground:** the `@teispace/teigeodata-wasm` build (the same files as the npm package)
  over the public layer, fetched once and opened with `Engine.openBytes`; search, reverse,
  admin, timezone, elevation, nearby, with MapLibre GL 6.18.0 drawing results over a map made
  from the pack itself. Nothing is sent anywhere.

- **Landing page and SEO (D-354):** the landing page follows teitunnel's (motion, sections,
  pill buttons, footer); every number on it comes from a gate's record or the released pack,
  and its code is cut from the example programs at build time. Each page has a canonical URL,
  an Open Graph card rendered at build (`app/og`), JSON-LD, and a place in `sitemap.xml`;
  `robots.txt` welcomes AI crawlers by name, as `llms.txt` does.

- **Docs by task (D-355):** one page per task with each language in a tab of one persisted
  group, generated by `site/scripts/guides.py`; step-by-step use cases; the old language URLs
  redirect to the install page.

## 3. Findings

**Fumadocs (npm, 2026-11-15).** `fumadocs-core` and `fumadocs-ui` 16.19.3 (published
2026-11-14), `fumadocs-mdx` 15.6.2, `create-fumadocs-app` 16.3.5. The scaffolder's static
template is the reference for v16 (read from its package, 2026-11-15):

- `next.config.mjs`: `createMDX()` from `fumadocs-mdx/next` wrapping `{ output: 'export' }`.
- `lib/source.ts`: `defineDocs({ dir: 'content/docs', docs: { schema: pageSchema,
  postprocess: { includeProcessedMarkdown: true } }, meta: { schema: metaSchema } })` from
  `fumadocs-mdx/macro`; `loader({ baseUrl: '/docs', source: docs.toFumadocsSource() })` and
  `llms(source, …)` from `fumadocs-core/source`.
- Search: `app/api/search/route.ts` exports `createFromSource(source).staticGET` as `GET` with
  `revalidate = false`, written at build time to a JSON index; the client uses
  `useStaticSearch` from `fumadocs-core/search/client`. Fumadocs warns that a static index is
  downloaded whole; its size is measured and budgeted here (§6).
- Agents: `/llms.txt`, `/llms-full.txt` and `/llms.mdx/<page>.md` are static routes.
- Styles: Tailwind 4 with `fumadocs-ui/css/neutral.css` and `preset.css`.

**Next.js 16.4.6** static export writes `out/`; `basePath` prefixes every route and asset, and
`images.unoptimized` is needed for `next/image` in an export.

**GitHub Pages (2026-11-15).** `actions/upload-pages-artifact` 5.0.0 (fc324d35),
`actions/deploy-pages` 5.0.1 (368f8252), `actions/configure-pages` 6.0.0 (45bfe019). The
repository's homepage is already `https://teispace.github.io/teigeodata`; Pages is not
enabled (`GET /repos/…/pages` is 404). A project site serves under `/teigeodata/`; a
`.nojekyll` file keeps `_next/` from being dropped. A file may be up to 100 MB and a site
1 GB.

**The data the examples and the playground use.** `world-np-lite.tgd` in
`data-2026.11.14.3`: the world's countries, first-level units and cities of 5,000 or more,
India's districts and towns, and Nepal in full, with names in Nepali, Hindi and English;
components point, admin, admin-index, names, search, boundaries, elevation, dem-coarse,
timezone and tz-rules; CC BY 4.0 with 11 notices. `tgd search Kathmandu` answers
`tgd:np/2cn`; `tgd elevation 27.7172 85.3240` 1,304.2 m (NASADEM). It has no postal
component, so postal examples use the Nepal pack's notes until a released pack carries one.

**The language API.** 31 `Engine` methods, `Store` and `Job` (15 and 7), records
`SearchOptions`, `OpenOptions`, `InstallOptions`, enums `Verify` and `Load`, seven free
functions (`bindings/idl.json`, format 7). Results are columnar blobs read in place by each
language's `Reader`. **Gap found:** the place outline (`boundary`) and the distance between
places are in the engine, the CLI and both servers (D-317) but not in the language API, so no
binding can draw a boundary. The product promises boundaries "ready for MapLibre, Google Maps
or flutter_map" in every language: this is a phase 7 step (§6).

**Toolchains on the maintainer's machine:** Rust, Node 26, Bun, Python 3.15, Go, Java 25,
Swift 6.4, Dart 3.14 and Flutter 3.50, clang; no .NET SDK (D-299) and no `kotlinc` (Kotlin
compiles through Gradle). Examples for .NET run only in CI.

## 4. Options compared

| Option | Strengths | Weaknesses | Verdict |
|---|---|---|---|
| **Fumadocs on Next.js, static export** | ADR-0024; MDX, tabs, includes, static search, `llms.txt` built in | Node toolchain in the repo | **Yes** |
| Starlight (Astro) | Fast, simple | Rejected in ADR-0024 | No |
| mdBook | Rust-native | Weak for per-language guides and a playground | No |
| Snippets in MDX, checked by a parser | Simple | Never run: output can lie | No |
| **Examples as programs with checked-in output** | What the reader sees ran; drift fails | A runner per language | **Yes** |
| Reference written by hand | Free-form | Drifts from the API | No |
| **Reference from the IDL, by the bindings generator** | One source; `--check` gates it | Template per language for signatures | **Yes** |
| A basemap from a tile service | Familiar look | A third-party request per view; keys or usage limits | No: our own outlines |

## 5. What we build ourselves, and why

- `site/`: the Fumadocs app, its pages and components (tabs per language, the playground).
- `site/examples/<language>/`: one program per guide, with `.out` files.
- `cargo xtask docs-examples [--check] [--lang L]`: runs them on the pinned pack.
- Reference, per-country and measured pages: generated, checked in, drift-checked.
- `.github/workflows/docs.yml`: build, check, deploy.

## 6. Impact on the plan

Phase 7 is drafted from this note ([phase 7](../../07-planning/phases/phase-7.md)): the site
and its deploy first, then the guides with executed examples, the generated reference, the
boundary in the language API, the generated pages, the playground, the exit review. The
static search index is budgeted (gzip at most 300 KB) once the pages exist.

## 7. Risks and open items

- Registries: until the maintainer's setup (the [release runbook](../../06-engineering/release-runbook.md)),
  packages install from release files and `git` tags; each guide says both, and which works today.
- No signed catalog yet (the key ceremony, Q-024): the store guide's code is compiled and run
  against a local test catalog, and says so.
- Pages needs the maintainer (enable, `DOCS_DEPLOY`).
