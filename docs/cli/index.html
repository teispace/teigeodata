Command line

tgd inspects, verifies, cuts and queries packs, manages the store, and serves packs over HTTP and MCP.

tgd is the command line of teigeodata: one static binary that looks inside packs, checks them, cuts smaller ones, answers every query in text, JSON, GeoJSON or Nominatim's format, installs and updates packs in the store, and serves them over HTTP and MCP.

Every example on this page ran

The commands below are cut from one script, tour.sh, which CI runs on the released pack world-np-lite.tgd and checks against the output shown.

Install

It installs from crates.io; there are no prebuilt tgd binaries yet. tgd completions zsh (or bash, fish, powershell, elvish) prints a completion script.

Every query takes --pack <file> (repeat it for several packs). Where packs disagree, the layer rule decides, not their order: the newer release, then the more specific pack. Without one, it answers from the packs installed in the store.

Look inside a pack

The full listing goes on with every source's notice, every section with its component and size, and the bytes of each component. tgd verify <pack> checks the head and every section's hash (--deep also decodes every value, --key checks the signature); tgd diff <old> <new> lists what changed between two releases, section by section and place by place.

--focus lat,lon ranks places near a point first: at the focus a place gains 30 points, and the gain halves every --scale-km (50 by default). --strict ranks by how well the name matched before anything else.

A place by its ID

Every query prints JSON with --json: one record per place, nulls where a value is unknown.

From a point

reverse gives the nearest places with their distance and bearing (from the place to the point, "3.2 km at 45° from Pokhara"); inside marks a place that holds the point: a unit by its outline, a settlement or locality within its radius of the point. --in-country never crosses a border.

Timezone and elevation

tgd tz also takes a place ID. The offset is computed from the tzdb rules inside the pack, at the current time.

Cut a smaller pack

extract writes a pack of the places in a box (with their ancestors and timezone areas), of some components, or both. The new pack is a normal pack: every query works on it.

--components point,names keeps only those components and what they need; with --bbox, --lod 3 stores coarser boundaries. tgd export <pack> streams every place out, in the order the pack stores them.

Postal codes

tgd postal 44600 finds the places a code names; --prefix completes a partial code; tgd postal <lat> <lon> gives the codes at a point. Codes are matched with or without separators, in any case and in any script's digits.

The store

The store keeps installed packs and the signed catalog that says which exist. It lives in the platform's data directory, or where --store or TEIGEODATA_STORE says.

CommandWhat it does
tgd initSet up the store: the catalog's mirrors and its trusted root.
tgd refresh [--countries a,b]Fetch what changed in the catalog.
tgd catalogList the catalog's packs, offline.
tgd find <name>Find a place by name with the packs that hold it, offline: what to install for "Dubai".
tgd locate <lat> <lon>The countries at a point, with their packs.
tgd install <packs>Install packs and their dependencies; --components, --names and --outlines install a part.
tgd updateUpdate installed packs to the catalog's releases.
tgd remove, tgd pinRemove a pack (and what nothing else needs), or keep one when room is made.
tgd status, tgd repairThe installed packs and their health; fetch what a damaged one lacks.

The signed catalog goes live with the first catalog release; until then, packs are downloaded from the data releases and opened with --pack. See the store.

Serve

tgd serve answers every query over HTTP, and tgd mcp over MCP for AI agents: see HTTP server and MCP server.
