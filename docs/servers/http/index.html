HTTP server

tgd serve answers every query over HTTP as JSON or GeoJSON, with Nominatim-compatible routes, from packs on local disk.

tgd serve puts the packs behind an HTTP API: every query as a GET route, native JSON or GeoJSON, and Nominatim-compatible /search, /reverse and /lookup so existing clients work unchanged. It is one process with no database: the packs are memory-mapped, and on Nepal it answers about 9,000 requests per second for the heaviest route (a large boundary) and 40,000 to 90,000 for the others, at 16 connections on one machine (measured by cargo xtask load, with a budget the load test enforces).

Native routes

Every route is GET /v1/<query> with query parameters, and answers {"results": [...], "attribution": "..."} (or "result" for one value). limit defaults to 10.

RouteAnswers
/v1/searchPlaces matching a name, best first, with score.
/v1/getOne place; names=1 adds every name with its language.
/v1/lookupPlaces by ID, in the order asked.
/v1/reverseThe nearest places with meters, bearing and inside.
/v1/nearThe places nearest a place.
/v1/adminThe admin units holding the point, country first.
/v1/hierarchyA place's ancestors, parent first.
/v1/childrenA place's children.
/v1/tzThe timezone with its offset, abbreviation and DST flag at t.
/v1/elevationThe terrain height, its datum, source and grid spacing.
/v1/distanceThe great-circle distance and initial bearing.
/v1/postalPostal codes and their places.
/v1/boundaryA unit's outline as GeoJSON.
/v1/coverageThe catalog's packs that cover a point (a server over a store).
/packsThe packs served, with their components, places and attribution.
/health{"status": "ok", "layers": n}.

Nominatim-compatible

/search, /reverse and /lookup speak Nominatim's API for the parameters its clients use, in the json, jsonv2 and geojson formats (JSONP is refused: use CORS):

RouteParameters
/searchq, or the structured amenity, street, city, county, state, country, postalcode; limit (at most 40, as Nominatim); countrycodes; viewbox and bounded; addressdetails
/reverselat, lon, zoom (how coarse a place to answer); addressdetails (on by default)
/lookuposm_ids: up to 50 teigeodata IDs, comma-separated

Point a Nominatim client, a geocoder plugin or a script at teigeodata and it works offline:

A conformance corpus of real client requests is checked in CI. Differences from Nominatim, where what cannot be filled is left out rather than faked:

  • place_id is a teigeodata ID (a string); there is no osm_type, osm_id, class, type or place_rank, so json and jsonv2 answer the same objects.
  • boundingbox is the place's point (south = north, west = east), not its extent; draw an outline with the native /boundary.
  • The address names the admin units by level as the country defines them.

Errors

A failure answers a stable code and an HTTP status:

The codes and their statuses are listed in the reference: invalid_argument and out_of_bounds answer 400 (a query string past the server's bound 414), not_found 404, missing_component 501, unavailable 503 and internal 500; unauthenticated 401, forbidden 403 and rate_limited 429 only from a deployment that adds keys, rules or limits.

Deploying it

  • Bind it where you mean to. It listens on loopback by default; behind a reverse proxy (Caddy, nginx), keep it there. With --listen 0.0.0.0:8080 it answers anyone who can reach the port.
  • Limits are built in. Every request is bounded (text length, limit at most 50, radius, time), so no request can make the server do unbounded work.
  • Floods and slow clients are bounded too. Connections and requests in flight are capped. A request head must arrive within 10 seconds, and an idle HTTP/1 connection is closed after the same time. HTTP/2 peers are pinged every 20 seconds (and dropped when they stop answering) and get at most 32 streams each. A request past the in-flight cap is refused at once, never queued, so a client should retry after Retry-After. A reverse proxy in front still does TLS and per-client rate limits.
  • Updates without restarts. Over a store, the server reads its journal every --follow seconds and serves newly installed or updated packs; queries in flight finish on the packs they started with.
  • Attribution comes with every answer, from the packs that answered it; keep it visible where the data is shown.
  • MCP is served at /mcp on the same port (Streamable HTTP): see MCP server.
